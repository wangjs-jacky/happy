# 按连接选择模型并跨连接新开会话

基线：`5b4af267`。用户明确选择“跨连接新开，保留旧会话”。设备默认账号、旧会话、旧草稿及运行中的任务均不由此功能修改；新会话不自动携带旧聊天内容。

## 实现

- 右下角按稳定的连接＋模型身份展示本机 Codex/Magpie 与用户拥有的 ChatGPT 账号。相同模型 ID 在不同连接中保留独立选项。
- 同连接更新原会话的下轮模型；跨连接先创建全新会话，成功加载后才导航。并发点击去重；账号/机器/路由归属变化、退出焦点、失败或延迟回复均不夺取旧页面。
- 新建页的连接选择与模型一起保存到草稿及首条提交快照。切机器清除此连接偏好；连接偏好不写设备默认绑定。
- 本机目录通过一次显式 `list-codex-native-models` 请求读取：独立原生进程、无推理、精确模型标识、分页上限、隐藏模型过滤、错误脱敏及退出清理。
- 新 `GET /v1/codex-accounts/directory` 仅读已有元数据，不调用旧版迁移。使用独立 URL，旧服务端返回404，不退回有迁移副作用的旧 GET。
- 新鲜账号授权可显式选择拥有的 profile，内部以命名的 `bindingVersion=-1` 标识。仅此精确值免于默认绑定比较；所有权、凭据版本、有效期和单次兑换仍校验。显式授权不能改挂已有账号会话或先于本次授权创建的原生会话；原登记重试幂等。旧隐式启动、原会话恢复及 service authority 路径保留。

## 交付边界

需要Server的新只读目录/显式授权与CLI的新目录RPC共同支持。旧端点不自动回退；旧CLI不可读取新目录时显示刷新失败，保留原连接模型。

本改动只有共享JS/TS，没有原生模块、权限、图标或runtime变化；后续发布可走现有OTA，无需因此重建APK。未发布生产Web/OTA、未更新活动CLI/daemon、未做真机验收或外部DeepSeek推理。PR前后截图已询问，未收到答复，不把Skills中的浏览器进度帧冒充用户要求的PR前后对照。
