## Gated three-device rollout — procedure only

Every stage below is **NOT EXECUTED**. These are the exact required stages, not commands to run during implementation:

```text
1. Merge the reviewed PR through main.
2. Publish a normal Paws CLI version containing the two environment RPC handlers.
3. Upgrade one non-server Mac as canary; verify daemon reconnect and inspect RPC.
4. Upgrade the second non-server Mac; repeat verification.
5. Upgrade the Mac that hosts production Happy services last; do not restart the server.
6. Publish the compatible App OTA only after all three daemons expose the RPC.
7. Scan all three devices, approve an idempotent no-op if already aligned, and apply a real upgrade only when Homebrew exposes a common newer target.
8. Verify each result with direct local commands and a second Happy scan.
9. Roll back a failed CLI runtime using the preserved previous runtime, then use SSH rescue guidance.
```

### Stop conditions and rollback limits

Pause progression on reconnect failure, missing RPC, changed machine identity, source mismatch, unverified result or server continuity concern. For an RPC timeout, wait for package work to finish and rescan before any retry; neither an acknowledgement timeout nor process timeout proves all Homebrew descendants stopped. Never overlap a rescue mutation with unresolved package work.

Stage 9 restores only a failed **Paws CLI/daemon runtime** using the previously preserved version and launch configuration, with the approved device-specific procedure. It does not automatically downgrade gh, roll back Homebrew metadata, repair credentials or reverse an App OTA. Recheck daemon reconnect and inspect RPC after runtime recovery, then use the displayed SSH/local-terminal rescue guidance if needed. A missing usable previous runtime blocks a claimed rollback path. No connection command is synthesized, no automatic SSH rescue exists, and no production server restart is permitted during recovery.

After these future stages, record actual device identities, versions, per-device results and direct/second-scan comparisons as new acceptance evidence. Until then, the tested local implementation and this decision package are the delivered outcome; production and real three-device acceptance remain unexecuted.
