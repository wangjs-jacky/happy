# Paws PC「休闲室内居家」沉浸皮肤设计

**日期：** 2026-09-27
**状态：** 待评审；仅设计，未实现

## 目标

让 Paws PC Web 获得参考图的核心体验：整页照片建立氛围，深色侧栏融入背景，问候语和输入框成为首页的视觉重心；进入会话后，延续同一语言并保持长时间阅读清晰。用户在外观设置中可以切换回原主题。项目、清单、会话、机器、模型和右侧能力面板沿用现有功能与数据。

设计以最终观感为优先。选择「可切换皮肤 + PC 布局与组件的定向改造」，既让效果完整，也让默认外观可恢复。参考图中的 Codex 导航结构和文案不是迁移目标；Paws 自身的信息组织仍应清楚。

## 已核实的来源

DreamSkin「休闲室内居家」，主题 ID `cecilylove002`，作者 `cecilylove`，版本 `0.1.0`。[原主题 ZIP](https://api.dreamskin.cc/v1/themes/ver_34a73ec14a33630c2578/download) 的 SHA-256 为 `3ade08bd0066142f1e97f684f28071dd3fa3a356fe65cf1f397e87f779c633e7`。包内有 `manifest.json`、`theme.json`、`background.jpg`、`theme.css`。`theme.css` 只有根节点背景色规则；截图中的圆角、侧栏和输入框排版不在该 CSS 中。

`theme.json` 提供的原始颜色：背景 `#131313`、半透明面板 `#1e1e1e55`、实色面板 `#2a2a2a`、强调 `#4b75a6`、次强调 `#6488b2`、高亮 `#7898bc`、装饰 `#b9a788`、正文 `#f0f0f0`、次要文字 `#939393`、线条 `#3f3f3f`。原包只声明深色外观。清单标注 `CC BY-NC 4.0`，图片来源摘要为「哲风壁纸」；正式分发原图前需明确其再分发权利。设计和开发期间可用本地原包评估，若无法取得合适授权，用同构图的自有图片替换，材质和布局方案保持不变。

## 设计决定

### 1. 整体画面

照片是一层贯穿 PC 工作区的背景，不作为聊天内容的直接底色。原图按 `cover` 裁切，初始焦点取包内 `focusX = 0.5`、`focusY = 0.5`，再针对常见视口校正，让人物面部和白猫在首页可见。照片上方有可配置暗色遮罩，首页中下部和侧栏文字区使用更强的局部渐变。静态资源随 Web 版本发布；无图、加载失败、减少透明效果时回退到 `#131313` 和实色表面，避免闪白或文字落在亮图上。

不要把 `#1e1e1e55` 当作所有组件的通用 `surface`。它仅是材质来源色：亮墙背景上的浅色文字会失去对比度。设计分四层：

| 层级 | 用途 | 首版视觉参数，最终以实机对比度校准 |
|---|---|---|
| 画布 | 照片、纯色回退、暗色渐变 | 图片可见，但在文字下方充分压暗 |
| 导航材质 | 主导航、清单侧栏 | 深色半透明，可轻微模糊；文字区域比原始 33% 更厚 |
| 内容材质 | 会话消息、代码、工具结果、右侧面板 | 接近实色，尽量避免照片纹理穿过长文本 |
| 浮层材质 | 输入框、菜单、弹窗、选择器 | 最稳定的深灰表面、细边框和必要阴影 |

这与 Apple 对材质的建议一致：较透明的表面适合保留背景语境，承载密集文字和操作的表面需要更强的可读性。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

### 2. 首页

- 左侧继续使用 Paws 的两级导航。主导航保持现有 60px 基本结构；清单栏初始目标宽度约 300–320px，用户原有拖拽宽度优先，不强行覆盖。窄视口按现有折叠规则收起次级栏。
- 当前白色大主区域改为无实色遮挡的照片画布。页眉控件悬于画布上缘，闲置时保持低视觉重量。
- 问候语移至输入框上方，二者形成同一内容轴。输入区约 780–900px 宽，随视口缩窄；与底边保持舒适距离，不紧贴窗口。人物与猫保留可见空间，不让控件覆盖面部。
- 输入框沿用现有机器、目录、Agent、模型和附件能力。把主要操作与次级配置分层排布；常用值可扫读，长路径截断后仍可查看完整内容。默认、悬停、按下、聚焦、禁用均有一致状态。
- 图片模式下取消首页粒子，以免照片与动态点争夺注意力；纯色模式可保留经过适配的粒子。动效只用于页面进入和主题切换，并尊重减少动画偏好。
- 页面中可能出现的图片生成入口、错误恢复、连接状态和右侧能力面板使用统一材质，不能局部露出旧浅色卡片。

### 3. 会话页

- 会话页延续同一照片与色彩，但正文阅读区域铺设高不透明度深色内容层；照片主要从侧边、页眉和内容间隙露出。长代码、diff、工具输出不叠在纹理上。
- 保持现有消息宽度和滚动行为。用户消息、助手消息、状态提示、代码块分别有清楚层级，选中、复制、链接和搜索命中仍可辨认。
- 输入框保持与首页相同材质语言和控件顺序；会话中应更紧凑，避免占据过多历史内容空间。
- 右侧能力面板打开时使用内容材质，不出现一块亮色面板；关合和宽度调整保持现有行为。
- 弹窗、搜索选择器、设置、悬浮菜单采用最厚的浮层材质，并用遮罩与照片分离。

### 4. 颜色、字体与状态

把原始颜色作为来源数据，映射到 Paws 语义 token。`accent` 用于主要操作；`accentAlt`、`highlight` 用于链接、焦点和少量高亮。成功、警告、错误保留各自语义，不直接改成主题蓝。交互表面区分 `surface`、`surfacePressed`、`surfaceSelected`，深色主题下不能残留焦糖主题的暖底。引用原图的暖色只用作克制的装饰。

PC 文本采用现有字体体系：问候语显著、会话正文稳定、标签与辅助说明克制。参考图里的文案和字体不是包资源，不直接复制。正文和占位文字目标对比度至少 4.5:1，识别控件所需边界、图标和键盘焦点至少 3:1；在照片最亮区域和不同裁切下检查，而非只核对静态色值。[WCAG 文字](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) · [WCAG 非文字](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 主题数据与迁移方式

外观设置增加一个完整的 PC 皮肤入口，展示缩略预览和「休闲室内居家」名称。皮肤选择保存为本设备的 `desktopSkinId`，在 PC Web 上优先解析为独立的深色语义主题与场景材质；原有 `themePack`、`themePreference` 和侧栏宽度继续保存，不被皮肤选择覆盖。关闭图片仅改变画布，不改变配色。关闭皮肤后，主题解析回到原有设置。系统明暗变化不打断启用中的深色皮肤；首版明确展示为深色皮肤，不把未经设计的浅色派生版伪装成同一效果。移动端继续读取原有主题设置。

迁移工具是**来源包适配器**，不是通用 CSS 注入器：

1. 校验 ZIP、`manifest.json`、内部文件哈希、相对路径、MIME 与资源大小。
2. 读取 `theme.json` 和图片，保留来源、版本与许可，生成可审阅的标准皮肤配置及资源清单。
3. 按显式映射表输出语义颜色与 PC 材质参数；原包未提供的圆角、间距、状态颜色标记为 Paws 设计值。
4. 报告未识别 CSS 和缺失 token；不执行脚本，不把原站点选择器注入应用。
5. 同版本重复导入得到相同结果。来源包更新时报告差异，由设计评审决定是否改变现有皮肤。

技术上复用 `themePacksData.ts`、`themePacks.ts`、Unistyles、外观设置中的语义主题机制；PC 专属皮肤配置单独描述图片、遮罩、材质和首页构图。PC 主题解析优先于原有主题包，关闭时退回现有解析；`desktopSkinId` 的缺省值为关闭。页面在 `ComposeHome`、`SidebarView`、`MessageComposer`、`SessionView`、`DesktopRightPanel` 等现有边界消费语义值。桌面宽度与折叠继续由现有布局系统管理。

## 交互与恢复

- 初次选中皮肤：预览、应用，立即可见；选择持续保存在本设备，刷新后不闪回浅色。
- 图片加载失败：回退纯色深灰场景，控件与正文保持可读；不阻断新会话或发送消息。
- 切换明暗：首版皮肤标明「深色」，不自动生成伪浅色；切换回其他 Paws 主题后继续使用其既有明暗偏好。
- 小视口：侧栏按已有规则折叠；照片重新裁切，问候语和输入区完整显示；附件和设置控件允许合理换行。
- 减少动画或透明效果：取消进入动效或使用不透明面板，不改变信息与操作。

## 验收与设计待决点

在 2048×1200、1440×900 和较窄桌面视口分别检查首页与有长文本、代码、工具卡片的会话页。检查照片焦点、侧栏密度、输入区重心、右侧面板、菜单、弹窗、错误状态，以及鼠标悬停、键盘焦点、选中与按下。用相同视口对比当前 Paws、DreamSkin 参考图与设计实现；静态画面之外，还应确认拖拽侧栏、发送消息和主题恢复均正常。

正式实现前的主要待决点是**背景图授权**。它影响最终使用哪张图，不影响本设计的构图、材质和主题架构。首轮视觉评审应优先比较两种会话页强度：A. 照片只在边缘明显可见；B. 照片透过消息周围的低对比度背景。以长会话可读性和整体氛围选择，不预设参考图的全部透明度为正确答案。
