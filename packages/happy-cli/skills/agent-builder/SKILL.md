# 我的 Agent

用户描述助手要做什么即可。信息够了直接创建；仅追问会改变职责的歧义。不要把模型、目录、思考强度变成必填问卷。

用户明确输入 `/agent` 时，在当前普通会话完成创建、修改或提炼，不切换会话、引擎或权限。如果 Happy 已直接提供本 Skill 全文，立即按其执行，无须再调用 `agent_builder`。只有 `/agent` 而没有请求时，先问用户想创建或修改什么助手，或想归档当前会话的哪种方法；不要从历史猜一个角色并保存。用户后续回答时继续本流程。

先用 `agent_list` 查看已有助手，避免同名重复。修改时用 `agent_get` 读取完整档案和 updatedAt，保留未被用户要求改变的字段；用 expectedUpdatedAt 防止覆盖其他设备的编辑。遇到冲突重新读取、合并，不盲目重试旧配置。

用 `agent_skills` 读取当前执行设备的真实 Skills 名称、描述和绝对路径。按职责挑选少量互补方法，为每项写明使用时机。名称是标识，含冒号也不是路径。查看所选 SKILL.md 中必要的工具/脚本依赖；缺依赖放进 setupNotes，未安装的 Skill 保留名称但不提供 path。不要伪造路径、工具或已验证状态。安装额外依赖须在用户授权范围内。

角色指令规定目标、工作方式、判断标准和输出偏好。对简单问题直接回答，只为确有帮助的任务调用相应 Skill。绑定 Skills 不扩大权限，也不要求每次跑全部方法。

用户说“狗头军师”时，以理清问题、挑战假设、依据事实做判断为核心；可匹配 sounding-board、grilling、web-search、show-me。辩论只在明确需要多方交锋时考虑，不能自动把每次回答变成辩论。

通过 `agent_save` 保存，创建时生成并复用 requestId；修改时传 id 和最新 expectedUpdatedAt。省略运行配置会沿用当前会话可用配置。只在保存工具成功后说已创建或已修改，并原样附上工具返回的 happy-agent 卡片；未执行、被拒绝或保存失败时不能报告成功。网络失败时查询同名档案或复用同一 requestId，不另造请求导致重复。

从会话提炼助手时，提炼可复用的职责和方法，不复制整段聊天、项目机密、凭据或无关任务内容。preferences 只保存用户明确要求长期记住的偏好；不要把会话全文当记忆。

修改完成后说明实际变化。归档和恢复都使用 `agent_archive`，分别传 archived=true 或 false，保留档案与会话。
